# fitness_privacy

运动(跑步/骑行)轨迹隐私保护库,解决三个问题:

1. **隐私区域自动识别** —— 用户无需手动设置
2. **轨迹起止点模糊化** —— 且能抵抗"沿轨迹走向反推"
3. **热力图敏感区域屏蔽** —— 防止公开热力图泄露保密单位位置与人员活动规律

同时保证:**距离统计与排行榜完全不受模糊化影响**。

## 核心设计:展示数据与统计数据分离

模糊化不影响统计的关键,是从数据流上把两者彻底分开:

```
原始轨迹(永不离开设备)
  ├─► ActivityMetrics.compute   → 距离/配速/爬升 → 排行榜、个人统计
  ├─► TrackSanitizer.sanitize   → 公开轨迹(仅用于地图展示)
  └─► HeatmapFilter.filterTrack → 热力图上传点
```

排行榜和统计只消费由**原始完整轨迹**算出的 `ActivityMetrics`;公开轨迹只是
展示用的折线,不参与任何计算。赛段(segment)匹配同理:在服务端用用户授权
的私密轨迹做匹配,公开页只显示排名,不显示轨迹。

## 1. 隐私区域自动识别 — `PrivacyZoneDetector`

把本机历史活动的**起点和终点**做 DBSCAN 密度聚类:家门口、公司楼下会自然
形成高密度簇,随机路过的地点不会。每个簇生成一个圆形 `PrivacyZone`。

- 全量计算在设备本地,历史端点与隐私区域**从不上传**;
- `minPts`(默认 3)防止偶尔路过的地点被误判;
- 区域半径 = 簇内最远端点距离 + 安全边距,且有下限(默认 200m);
- 用户手动设置的区域与自动区域合并使用,手动优先。

## 2. 起止点模糊化 — `TrackSanitizer`

简单截掉起止点为什么不够:轨迹出区域后若仍是直线,攻击者把可见轨迹反向
延长即可推出被截段指向;多条轨迹的延长线交叉就是住址。本实现三层防护:

| 层 | 措施 | 防什么 |
|---|---|---|
| 1 | 裁到完全离开隐私区域 | 直接暴露家门口 |
| 2 | 每次活动随机扩展裁剪半径(用户盐+活动ID 做种子) | 多次活动截点连成圆环,圆心即住址 |
| 3 | 出区域后继续裁到"安全截点":轨迹发生明显转向(≥35°)且满足最小附加距离 | 沿直线走向反推来路 |

附加裁剪距离同样按活动随机(150–600m)。裁剪结果对同一 (用户盐, 活动ID)
可复现,重新上传时公开轨迹不变;盐只存在本地。

整条轨迹都在隐私区域内(如小区内短跑)时,公开轨迹为空,但统计数据完整保留。

## 3. 热力图屏蔽 — `HeatmapFilter` + `HeatmapAggregator`

两道防线:

- **客户端过滤**:落在隐私区域(含额外边距)或敏感区域多边形内的点,
  **根本不上传**热力图管道 —— 服务端被拖库时这些点不存在,才是真保护。
  敏感区域(保密单位等)以多边形形式由服务端下发,客户端只存几何、不知含义。
- **服务端 k-匿名聚合**:即使单点都合法,某偏远格子长期只有 2–3 人活动
  本身就是信号(正是 Strava 热力图事件的教训)。聚合按网格统计去重用户数,
  不足 `minUsers` 的格子不下发、不渲染。

## 使用

```dart
// 1. 定期(如每次活动结束后)在本地重新识别隐私区域
final zones = const PrivacyZoneDetector().detect(allHistoricalEndpoints);

// 2. 活动结束上传前
final result = const TrackSanitizer().sanitize(
  rawTrack: raw,
  zones: zones,
  activityId: activity.id,
  userSalt: localSalt, // 首次启动生成的随机串,仅存本地
);
upload(publicTrack: result.publicTrack, metrics: result.metrics);

// 3. 热力图贡献
final heatmapPoints = const HeatmapFilter()
    .filterTrack(raw, zones, await downloadSensitiveAreas());
```

运行测试:`dart test`

## 已知边界

- 转向检测基于航向窗口(默认 60m),GPS 漂移严重时会退化为按最大附加距离
  裁剪,隐私性不降、可见轨迹略短;
- 圆形区域是对住址分布的近似,若用户家紧邻狭长绿地等异形区域,可叠加
  手动多边形区域(扩展 `PrivacyZone` 即可);
- 真正的端点保密依赖"原始轨迹不出设备"这一前提,需配合传输与存储加密。
